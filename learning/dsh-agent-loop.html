00 · 内核 · 第 1 遍

先握住内核：七行伪代码

别从图开始。任何 agent 框架——Claude Code、这套 harness、你自己手搓的玩具——内核都是同一个循环：

while (true) {
  回复 = 模型( system + 历史 + 工具表 )    // 一次流式请求
  历史 += 回复
  调用 = 回复里的 tool-call 块
  if (调用为空) break                   // 模型不再要工具 → 这轮说完了
  for (c of 调用) 历史 += 执行工具(c)    // 结果以 role:'tool' 回到历史
}

这七行就是 step() 的骨架；整个 packages/core 做的所有事，只是把它加固成生产级。加固恰好落在四个方向上，于是全页可以分五遍读——每一遍只新增一个关注点：

  1. 第 1 遍只记内核。上面七行就是全部，先别看任何图。
  2. 第 2 遍换掉「历史变量」。历史不是内存数组，是追加式日志：写靠 append 事件，读靠 deriveMessages() 全量投影。记一句话：模型可见 ⟺ 已落日志。 → 图 01 · 图 06
  3. 第 3 遍给循环起名字。一次「问模型 + 跑工具」叫 step；处理完一批输入、不再欠答复叫 turn。输入统一走收件箱，分 followup / steer / inject 三个口。 → 图 02 · 图 03
  4. 第 4 遍找到插口。循环每个关键动作前后都留了 waterfall 挂点（琥珀虚线框）：改提示词挂 pre-step，权限审批挂 pre-execute，超时挂 execute 环绕。 → 图 03 的琥珀框 · 图 05
  5. 第 5 遍工程角落。并发怎么调度、中止怎么排干、失败怎么落日志——让内核在生产里站得住的细节，用到再查。 → 图 04 · 各图红色路径

01 · SESSION LOG · 第 2 遍

单一事实源：一切先落日志，再投影成请求

整个 harness 只有一条铁律级的数据通路：模型可见 ⟺ 已落日志。用户输入、模型的每个流式分片、每次工具调用与结果，都以事件形式追加进会话日志；而发给模型的请求不做增量拼接——每个 step 都调用 session.deriveMessages() 从日志全量投影出完整历史。fork、resume、转录、遥测全部由同一条事件流派生。

02 · PHASE & INBOX · 第 3 遍

Agent 状态机与收件箱：输入怎样唤醒循环

一个 ReactLoopAgent 只有三个内部相位：idle、running、maintenance（压缩等维护任务独占时使用）。所有输入走同一个收件箱，但入口语义不同：followup 排队到下一个 turn 并唤醒；steer 插到当前 turn 的下一个 step 并唤醒；inject 只投放上下文、不唤醒，静静等别的消息带它上车。中止后到达的唤醒会被重新归类到 next-turn——被 abort 的活动不能再接客。

03 · TURN & STEP · 第 3 遍（琥珀框属于第 4 遍）

04 · SCHEDULING · 第 5 遍

工具调度：执行可以重叠，提交永远按模型顺序

一步里模型可能一口气发多个调用。调度器（executeToolCalls）按并发模式分组：只有工具的 isConcurrencySafe(args) 精确返回 true 才算并行，缺失、返回别的值、抛异常一律按独占处理（fail-closed）。并行调用进一个上限为 maxParallelToolCalls 的滚动池；独占调用是屏障——等池排干后独自运行。无论执行怎么交错，tool/result 一律按模型发起顺序提交。

05 · TOOL PIPELINE · 第 4 遍

单次工具调用：三段流水线，处处可挂策略

调度器把每个调用交给工具注册表的三段流水线。prepare 决定能不能跑：参数快照冻结、tools/pre-execute 策略（允许 / 拒绝 / 请示审批）、单调 guards。dispatch 真正执行：tools/execute 环绕层（超时、重试、指标）包着工具本体。finalize 收尾：tools/post-execute 可替换或拦截结果（如超长文本外溢成预览 + 定位符），最后无损物化并通知观察者。

06 · ROUND TRIP · 第 2 遍

结果回流：从工具产物到模型的下一句话

流水线的产物不会直接塞回请求。它先被包成一条 user 角色、内含 tool-result 块的消息，作为 tool/result 事件落日志；下一个请求构建时经投影进入历史，最后由 DeepSeek 适配器展开成独立的 {role:'tool'} wire 消息发上线。模型读到结果，产出下一条 assistant——回到 03 图的循环。
